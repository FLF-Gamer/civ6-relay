# 六人网络测试记录

日期：2026-10-30。运行原版 EasyTier 2.6.4、六个独立凭据和真实 TUN/UDP，覆盖 15 对玩家、30 个通信方向。测试没有启动文明6游戏实例，不能替代六台 Windows 玩家的完整对局。

## 结果

六个客户端可自动建立 P2P；部分直连失败时，只有受影响的玩家对回退至服务器，其他玩家对继续直连；全部直连失败时，全部经服务器中继。恢复公网通路后可重新直连。直连稳定后服务器仍有协调与心跳流量，但不承载这里测到的游戏测试数据。

切换有明显中断，不能称为无缝回退。1Mbps 是否能支持六人实际文明6对局，仍取决于游戏真实流量；本次低负载通过，高负载出现明显丢包。

## 六个独立 NAT 的受控模拟

每个客户端在独立 Linux 网络命名空间、独立私网和 NAT 后运行；不共享客户端局域网。入站使用 conntrack 过滤，UDP 使用稳定端口映射；六个 NAT 均被后端识别为 PortRestricted。没有固定客户端监听端口，使用后端实际打洞。

每位玩家的公网接入双向各加 20ms 延迟与 1ms 抖动，中继接入双向各加 10ms 与 1ms 抖动；因此理想直连 RTT 约 80ms，中继 RTT 约 120ms，再加序列化、排队和软件处理。中继出口使用 netem 1Mbps 限速、80 包队列。所有网络、防火墙和转发改动仅在 `--network none` 的一次性容器内。

轻负载：每个通信方向每秒 2 个 256 字节 UDP 请求，接收端原样回包；30 个方向合计净荷约 245.76kbps，另有 IP、加密和组网开销。使用 UDP 62056。该负载是合成数据，不是文明6抓包。

| 稳定阶段 | RTT 中位数 ms | RTT P95 ms | 丢包/请求 | 服务器发送 kbps |
|---|---:|---:|---:|---:|
| 全直连：15 对 | 83.87 | 87.74 | 0/959（0.00%） | 3.54 |
| 部分中继：3 对（仅统计这 3 对 RTT） | 131.63 | 137.05 | 0/191（0.00%） | 87.65 |
| 其余 12 对保持直连 | 83.17 | 87.86 | 0/768（0.00%） | 87.65 |
| 全员中继：15 对 | 133.92 | 139.84 | 0/959（0.00%） | 431.30 |
| 全部恢复直连 | 84.26 | 88.39 | 0/959（0.00%） | 2.83 |

部分中继时，服务器发送量是一整台服务器的统计值；两行的 RTT 与丢包分别按中继 3 对、直连 12 对统计。

- 六个客户端近同时启动，全部 15 对完成直连约 9.72 秒；期间服务器发送约 99.70KiB、接收约 91.68KiB。
- 阻断 1↔2、3↔4、5↔6：六个方向均变为 2 跳，下一跳均为 `Civ6Coordinator`；其余 24 个方向保持 1 跳。受影响方向从执行断路到再次收到成功响应约 11.52–17.75 秒。
- 再阻断所有玩家间公网通路：30 个方向全部变为经协调服务器的 2 跳；新增失去直连的 24 个方向恢复响应约 11.77–23.33 秒。此前已经中继的 3↔4 在该阶段也各丢失 1 个请求，其余已有中继方向无丢包。稳定后 959/959 次往返成功。
- 解除阻断：观测到全部恢复直连约 14.74 秒；恢复阶段 4199/4199 次往返成功。路由每约 2 秒采样，打洞和响应时间还受每方向 2pps 的测量分辨率影响。
- 六端默认路由保持不变。客户端禁止转发其他玩家数据，所有观察到的 2 跳均通过服务器，没有借其他玩家转发。

高负载阶段提高为每方向每秒 4 个 494 字节请求加回包：仅净荷约 948.48kbps，加封装后超过 1Mbps。此次模拟中丢包 20.17%，RTT 中位数 1450.11ms、P95 4053.99ms，另有超过 1 秒才到达的响应 1111 个。说明排队和丢包都可能恶化，平均 RTT 不能单独用来判断是否适合对局。

模拟允许协调连接同时使用 UDP/TCP，玩家间直连观察为 UDP；真实公网复核强制外层 UDP。模拟队列与云平台的限速行为不同，二者过载时的 RTT 不能直接互换。模拟进程运行在本机容器中，CPU 与内存不能当成部署服务器性能。

## 已部署服务器的六客户端公网中继

六个一次性容器使用六份临时独立凭据连接现有部署，强制关闭 P2P，以确保所有游戏测试数据经过真实服务器。30 个方向均核实为 2 跳、下一跳为协调服务器。六个客户端共享本地公网出口，所以这部分验证公网中继延迟和负载，不代表六个异地运营商 NAT；自然断链回退由上一节验证。

| 阶段 | RTT 中位数 ms | RTT P95 ms | 丢包/请求 | 服务器网卡发送 kbps |
|---|---:|---:|---:|---:|
| 首包冷启动 | 80.36 | 137.29 | 1/179（0.56%） | 133.75 |
| 稳定轻负载 | 76.25 | 91.31 | 0/1199（0.00%） | 366.65 |
| 高负载 | 78.67 | 100.97 | 263/2399（10.96%） | 1137.30 |
| 降回轻负载 | 78.43 | 102.70 | 0/1199（0.00%） | 366.14 |

首包冷启动为每方向 1pps、128 字节、6 秒。轻负载与高负载参数同上，各持续 20 秒。首轮未预热轻负载曾出现 3/1199 个丢包；复核将冷启动单列，再测稳定负载、过载和降载恢复。单次零丢包不能承诺长期零丢包。

服务器轻负载 CPU 约 1.44%（按单核计），常驻内存约 32.55MiB；高负载 CPU 约 1.73%，内存约 32.35MiB。这个负载下，瓶颈表现为网络交付丢包，CPU 仍较空闲。

发送/接收速率是对应测量窗口内的接口字节差值；公网统计包括 SSH、协调流量及其他系统流量，也可能在云平台限速前计数，不等于限速后成功交付的带宽。RTT 由发送客户端自己的单调时钟测量，不依赖跨机器校时；丢包指测试结束额外等待 2 秒后仍未收到回包，超过 1 秒的迟到另计。

测试结束已撤销六个临时凭据、删除六个临时容器和私密配置；只保留原有 player1/player2。中继、防火墙、审计和 SSH 均 active，未重启生产中继或修改生产防火墙。

```bash
# 先按 validation.md 准备 .build/client-test.toml 和测试镜像。
docker run --rm --privileged --network none --platform linux/amd64 \
  -v "$PWD:/workspace" civ6-mesh-test:local \
  python3 -u /workspace/tests/six_player_network.py

# 公网测试先建立已认证 SSH control socket；端点通过环境变量提供。
# 仅针对获授权的既有服务，脚本自动创建/撤销临时凭据。
MESH_TEST_ENDPOINT='<服务器地址>' python3 -u tests/six_player_wan.py \
  --socket /private/tmp/civ6-relay-ssh-six
```

持续发包和回包由 `tests/mesh_traffic.py` 执行，不使用路由列表中的估算延迟替代游戏数据 RTT。
