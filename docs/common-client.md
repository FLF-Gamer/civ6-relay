# 3.2 通用客户端验证

所有玩家使用同一个 Windows ZIP。首次只填写昵称、服务器 IP、端口，无需申请、输入或导入个人接入信息。
同一份可复用接入配置由程序直接携带；客户端首次在本机生成并保存不同的实例 ID。
后端以 `dhcp = true` 和明确的 `dhcp_subnet` 自动分配私有游戏地址，避免复制同一个固定 IP。
并发入网时随机选择空闲候选地址，后续只有实际冲突才重新分配；不在每包路径上执行分配逻辑。

后端构建 `2.6.4-civ6.2` 保留快速中继补丁，增加可选的 DHCP 子网设置。
服务器继续不创建虚拟网卡，不设置默认路由、DNS、转发或 NAT。

## 实际测试

日期：2026-10-30。真实二进制、六个独立 NAT、15 对玩家、30 个方向，模拟中继出口 1Mbps。
六个客户端使用完全相同的接入密钥，分别生成本机实例 ID，自动取得六个不同的虚拟 IP。
地址稳定检查通过；整个测试继续使用这些地址完成收发。具体地址和原始数据见 [六人同包结果](common-client-simulation.json)。

| 场景 | 结果 |
| --- | --- |
| 全部直连 | 959/959 往返成功 |
| 路径慢但仍可达 | 1200/1200 成功，提前中继 |
| 外层复制 UDP 包 | 479/479 成功，游戏套接字重复交付为 0 |
| 三对断链 | 恢复范围 0.786–0.997 秒；受影响方向丢 19/600；其他方向 2400/2400 |

切换阶段仍会丢包；这些是合成 UDP 测试，没有启动六个文明6实例。
PowerShell/C# 检查通过，验证同包在两台电脑上实例 ID 不同，重连身份保持、没有固定虚拟 IP。
管理端 8 项测试通过，包括通用配置只生成一次、重复打包复用同一配置、通用包不含本机 ID、IP、服务器地址或网络主密钥。
Windows PE 已生成；真实 Windows 驱动、GUI 和文明6完整对局仍需实机验证。

## 复现

按 validation.md 生成客户端配置测试模板，并为 client.Tests.ps1 加上
`-SharedConfigOutput /workspace/.build/common-client-test.toml`。
在一次性特权 Linux 测试容器内执行：

```bash
MESH_TEST_FAST=1 MESH_TEST_COMMON=1 python3 -u tests/six_player_network.py /workspace/.build/common-six-simulation.json
```
