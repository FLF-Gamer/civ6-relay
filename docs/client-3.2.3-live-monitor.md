# 3.2.3 实时延迟与运行日志

客户端新增“网络状态”和“运行日志”两页。此次按要求不新增抓包，也不记录逐包 UDP 收发；原有广播转发引擎和按需累计计数保持原有行为。

## 延迟的含义

- 端到端 ICMP：每秒探测当前游戏 /24 中玩家的虚拟 IP，测量完整直连或中继路径的往返时间。最多 8 个并发探测；未回应、不可达、等待、停止及过期分别展示，失败不伪造为 0 ms。实际成功的本机或极低延迟结果可为 0 ms。
- 底层链路 RTT：保留引擎的下一跳测量。直连时是到玩家的链路；中继时只到中继，不代表玩家间总延迟。
- ICMP 与游戏 UDP 是不同测量；Ping 被防火墙阻止时，游戏仍可能正常。采样时间表示该次 ICMP 结果时间，不能用来证明 UDP 收到。

## 执行与资源

后台 C# 组件每秒执行一次本机 CLI 路由查询，3 秒超时，输出有上限。窗口计时器只读取快照并更新控件；ICMP 使用异步 API。只终止自己创建的查询进程，不停止组网引擎。切换组网实例及删除、重新加入的玩家不会接受旧的在途结果。

日志记录实际操作结果、玩家路由出现/消失、路径改变与查询错误；不把每次 RTT 波动当成一条事件。队列最多 1000 行，每次取 200 行，显示达到 160000 字符时批量裁到 120000 字符，避免无限增长。复制与导出由玩家主动操作。

## 验证范围

离线 Linux PowerShell 容器通过以下验证：

- C# 5 语法编译，真实本机 ICMP 成功与不可达失败，失败 RTT 为空。
- 真正启动慢 CLI，确认 3 秒超时终止自有查询进程、停止及重启不等待查询完成；无关进程与组网引擎继续运行。
- 真实打包引擎和 CLI 的路由 RPC，中文昵称、缓存界面读取、ICMP 与下一跳 RTT 分列。
- 实例切换和损坏连接记录清理旧采样，过期路径明确标记，超量输出及日志队列有界。
- 通用客户端、组件修复、状态解析、按需局域网诊断及 8 项服务端单元回归通过。

测试源码见 `tests/client-live.Tests.ps1` 和既有客户端测试。Linux 下 C# 5 编译与真实 RPC/ICMP 测试不能代替 Windows PowerShell 5.1、.NET Framework、WinForms 布局或文明6实机对局验证。尚未验证玩家间实际延迟和房间发现故障。
