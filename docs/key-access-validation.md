- Python 服务端和打包回归共 29 项通过。覆盖默认关闭 Key、显式开启、共享、人数与房间上限、首次使用计时、到期拒绝、会话释放、重启恢复、免费模式、单实例锁和私有配置不进入公开包。

- `tests/key_network_integration.py` 通过。真实组网核心、三客户端、隔离 STUN 和网络命名空间验证同 Key 玩家发现、P2P 直连、自动 IP、UDP 往返、广播回复、不同 Key 玩家隔离、在线撤销、名额重新使用、到期拒绝和已有 P2P 通路清理。

## 时间与平台边界

网络测试将服务端有效时间缩短为 90 秒，等待真实时钟到期，没有伪造组网选路或核心授权状态。48 小时计时及断开后不延长由服务测试验证，没有实际等待 48 小时。

组网核心已建立连接的到期清理周期最长 60 秒。客户端后台按在线租期结束连接，另测了续期无响应时不会继续等待到 HTTP 超时。测试没有运行文明6或六人完整游戏对局，不能作为公网延迟或服务器承载人数的测量。

本次没有运行原生 Windows PowerShell 5.1 / WPF、驱动或真实玩家电脑。Windows 工作流已加入 Key 接口及 UI 场景，尚未执行；本地 PowerShell 7.5 结果不能替代这些验证。公网 HTTPS 接口尚未部署或联调。

## 复现入口

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

在离线 PowerShell 测试容器中执行 `tests/client-key.Tests.ps1`；在具备 iproute2 的一次性特权 Linux 容器内执行 `tests/key_network_integration.py`。两者均以 `/workspace` 挂载仓库。不要在生产服务器直接运行隔离网络测试。
